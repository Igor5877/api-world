# Наступна дія: оновлення островів «лише різниця» (як rsync)

Статус: **зроблено 2026-10-06** (api-world cb16efa3, агент 43df241, задеплоєно на dev).
Перевірено на острові Test: перший прогін — повна заливка 964 файлів за 115 с і
відбиток; далі 1,5 с «без змін 964»; ручна правка kubejs-файлу відновлена з репо,
підкинутий jar у mods/ видалено (1,9 с). Ядро (libraries/, core-файли) поки
заливається по-старому.

## Навіщо

Зараз кожне оновлення з рестартом **повністю** перезаливає теки з модпак-репо
(`mods/`, `config/ftbquests`, `kubejs/`, `defaultconfigs/`, ядро) — навіть коли
змінився один файл. Повна заливка з'явилась (липень 2026), бо файли на острові
можуть змінити **вручну** (lxc file push, консоль) поза git і API — і без неї
острів назавжди лишився б з «чужим» файлом («мішанина»: дві версії мода,
417 файлів kubejs замість 190).

Ціна: острів ~2,5 хв, Spawn простоює кілька хвилин (лише `mods/` — 1 хв 13 с).
У v0.0.37-both змінилось 4 jar, а заливалось ~200 файлів на кожен острів.

**Мета:** та сама гарантія «на острові рівно те, що в репо», але заливати лише
те, що реально відрізняється, — секунди замість хвилин.

## Як (quick-check rsync: розмір + час зміни)

1. **Відбиток після кожної заливки.** Після push записати маніфест острова:
   `{шлях: (розмір, mtime)}` для всіх файлів синхронізованих тек. Зберігати на
   хості (поруч із бекапами: `UPDATES_BACKUP_DIR/<контейнер>/sync-manifest.json`),
   не в контейнері.
2. **Перед оновленням — список файлів з острова** з розмірами й часом, без
   вмісту. Робить crash-агент (новий запит, напр. `POST /stat?container=…&dirs=…`):
   він уже читає файли через SFTP LXD, і **зупинених** контейнерів теж.
3. **Порівняння трьох станів:** git нової версії · наш маніфест · реальний стан.

   | Ситуація | Дія |
   |---|---|
   | файл не мінявся з нашої заливки і не змінився в git | не чіпати |
   | змінився / з'явився в git | залити |
   | розмір чи mtime ≠ маніфесту (**правка вручну**) | перезалити з репо |
   | файлу немає в репо (підкинутий вручну / видалений у git) | видалити |
   | файлу з репо немає на острові | залити |
   | маніфесту немає (перший раз, старий острів) / агент недоступний | **повна заливка, як зараз**, потім записати маніфест |

4. **Підстраховка:** повна заливка за командою адміна і, напр., кожне N-те
   оновлення — вирівняти те, що quick-check міг пропустити (правка зі збереженим
   mtime і розміром — практично не трапляється).

## Деталі, про які не забути

- `mods/` — головний виграш: великі jar, міняються рідко. Підмінений jar ловиться
  за розміром/часом, підкинутий — видаляється.
- `config/` синхронізується **не повністю**: чиститься лише `config/ftbquests`
  (`CLEAN_SYNC_SUBDIRS`), решта конфігів острова — його власні. Порівнювати й
  видаляти «зайве» лише в межах тих самих правил, що й зараз (`CLEAN_SYNC_DIRS`,
  `CLEAN_SYNC_SUBDIRS` у `git_sync.py`).
- Ядро (`CORE_SYNC_FILES`, `libraries/`) — так само, але `libraries/` великий:
  саме тут економія для core-оновлень.
- Шаблон `skyblock-base` і Spawn — той самий механізм (Spawn простоює найдовше).
- Бекап файлів перед оновленням (`backup_files`) — лише тих, що замінюються/
  видаляються (зараз — за `changed_paths`).
- Discord (`update_notifier.island_done`): «залито N, видалено M, виправлено
  вручну змінених K» — видно ручні правки.
- Тести: кожен рядок таблиці вище; маніфест відсутній → повна; агент недоступний
  → повна; ручна правка → перезалито; зайвий jar → видалено.

## Також у черзі (з сесії 2026-10-06)

- Spawn перед рестартом у кампанії: відлік у чат (60/30/10 с), для `-both` —
  «оновіть клієнт». Зараз Spawn перезапускається без попередження.
- М'яке оновлення без рестарту: рядок у чат острова «застосовано».
- Watchdog: не зупиняти острів, якщо серія знімків потоків показує «рухається»
  / «простоює» (хибні зупинки через загублений WebSocket після unfreeze).
- Спейр, знятий з видачі після публікації шаблону, видаляється з неточним
  підписом «no spare_ready after Ns» — писати «template changed».
- Лаунчер: модуль DiscordGame чекає Discord без тайм-ауту (лаунчер «висить»,
  доки Discord не закрити) — перевірити, чи повторюється; за потреби
  `"enable": false` у `/root/config/DiscordGame/Config.json` + `build`.
