# FreesiaII для клієнтів Forge 1.20.1

Цільова конфігурація: **YSM 2.6.5**. Це серверний міст, не заміна клієнтського YSM.

| Компонент | Середовище | Що встановити |
|---|---|---|
| Клієнт | Minecraft 1.20.1, Forge | YSM 2.6.5 для Forge 1.20.1 |
| Ігровий сервер / острів | Minecraft 1.20.1, Forge 47.4.0+ | `freesia-backend-forge-1.0.0-mc1.20.1.jar` у `mods/` |
| Проксі | Velocity, Java 21 | Freesia-Velocity з цього каталогу та PacketEvents |
| Worker | Fabric, Minecraft 1.21.1, Java 21 | Freesia-Worker, Fabric API, YSM **2.6.5 для Fabric 1.21.1** |

Worker лишається на Fabric: клієнт підключається до ігрового Forge-сервера через
Velocity, а Freesia окремо обмінюється YSM-пакетами з Worker. Не додавайте Worker
до списку ігрових серверів Velocity. Використовуйте однакову версію YSM на
клієнтах і Worker; канал upstream для гілки 2.6 — `yes_steve_model:2_6_0`.
JAR 2.5.3, наданий під час розробки, має інший канал (`2_5_3`) і не підходить
до цієї конфігурації.

## Збірка

Forge Backend — окремий Gradle-проєкт, Java 17:

```sh
cd Freesia-Forge
./gradlew build
```

Результат: `Freesia-Forge/build/libs/freesia-backend-forge-1.0.0-mc1.20.1.jar`.
Gradle запускає тести та remapping (`reobfJar`) для використання на звичайному
Forge-сервері. В JAR не пакуються Forge, Minecraft або клієнтський YSM.

Проксі й Worker — upstream multi-project build, Java 21:

```sh
./gradlew :Freesia-Velocity:build :Freesia-Worker:build
```

Для Velocity використовуйте shaded `*-all.jar`, для Worker — remapped JAR
із його `build/libs/`. Налаштування адрес та mTLS описані в [README](README.md).
Збережіть чинну конфігурацію підключення ваших Forge-серверів через Velocity:
цей мод не реалізує Forge handshake або пересилання UUID/IP.

## Реалізовано

- Відстеження реальних гравців через Forge `StartTracking` / `StopTracking`.
- Сумісні з FreesiaII повідомлення `freesia:tracker_sync`: запит, відповідь,
  сповіщення про нового спостерігача.
- Повторне сповіщення про себе після входу, респавну та зміни виміру.
- Видалення зв'язків спостереження після виходу, очищення після зупинки сервера.
- Обробка стану тільки на серверному потоці; декодування пакетів до постановки
  завдання в чергу, перевірка довжини й формату вхідного запиту.
- Відсутність вимоги встановлювати Backend на клієнт.
- У Velocity Freesia перехоплює лише свій канал YSM, щоб не блокувати інші
  зареєстровані plugin channels.

Citizens / Bukkit events / API віртуальних NPC не перенесені в Forge Backend.
Вихідні Paper/Waterfall-модулі збережені як частина upstream, але вони не є
Forge-модами. Підтримка моделей реальних гравців не потребує Citizens.

## Перевірка перед використанням на основному сервері

Збірка та тести стану не доводять наскрізну сумісність клієнта, проксі й Worker.
Потрібен стенд з двома клієнтами **YSM 2.6.5 Forge 1.20.1**:

1. Вхід обох гравців, вибір і зміна моделі, синхронізація анімацій.
2. Вихід за дистанцію відстеження й повернення; спостерігач бачить актуальну модель.
3. Смерть/респавн, зміна виміру, перехід hub → острів → інший острів.
4. Вихід і повторний вхід, зупинка/старт острова та перезапуск Worker.
5. Перевірка інших мережевих модів і відсутності помилок channel/packet decoder.

У схемі Freesia YSM обробляє Worker. Не вмикайте одночасно незалежну локальну
обробку YSM на ігровому сервері без окремої перевірки: два джерела пакетів
можуть конфліктувати. Перевірте склад серверного модпаку на стенді.
