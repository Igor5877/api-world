# Інструкція з інтеграції мода RealMarket для системи Nestworld

Цей документ описує технічні вимоги та архітектуру для розробника мода `RealMarket`, щоб забезпечити його повноцінну роботу в екосистемі Nestworld (api + mods-server + hub).

## 1. Загальна архітектура екосистеми Nestworld
Наша система складається з трьох основних компонентів:
1. **Hub Server (Спавн):** Сервер, де гравці завжди онлайн, взаємодіють один з одним та купують предмети в магазинах інших гравців.
2. **Island Servers (Острови):** Окремі сервери для кожного острова/команди. Вони можуть бути вимкнені (сплячий режим), коли гравців немає онлайн, і автоматично запускаються при необхідності.
3. **API Server:** Центральний бекенд (FastAPI), який керує станом островів, WebSocket-з'єднаннями та зберігає дані в Redis/БД. Всі сервери спілкуються через WebSocket.

## 2. Блок "Market Link" (Підключення до AE2)
На сервері острова гравець повинен мати можливість підключити свій магазин до мережі Applied Energistics 2 (AE2).
- **Реалізація блоку:** Необхідно створити спеціальний блок (наприклад, `Market Link`), який підключається до ME Мережі (повинен реалізовувати інтерфейси AE2 для доступу до інвентарю мережі).
- **Прив'язка до острова/команди:** Щоб уникнути зловживань та плутанини, цей блок повинен жорстко прив'язуватися до ID команди гравця та конкретного острова при встановленні. (Можна використовувати існуючий `NestworldModsServer.ISLAND_PROVIDER` для перевірки).
- **Унікальність:** Рекомендується обмежити кількість активних `Market Link` блоків для одного острова/команди.

## 3. Синхронізація залишків (Inventory Sync)
Оскільки острів може бути вимкнений, Hub-сервер повинен знати актуальну кількість товарів для продажу.
- **Періодичність:** Блок `Market Link` повинен сканувати ME Мережу і відправляти кількість доступних для продажу предметів через WebSocket на наше API:
  - Періодично, кожні 2-3 хвилини (щоб фіксувати зміни з автокрафтів).
  - Обов'язково при старті сервера острова.
  - Обов'язково при зупинці/вимкненні сервера острова.
- **Збереження:** API записуватиме ці дані в Redis. Таким чином, Hub-сервер завжди знатиме, чи є товар у наявності, навіть якщо сервер острова вимкнений.

## 4. Процес покупки та система "Боргу" (Debt System)
Для забезпечення миттєвої покупки на Hub-сервері (щоб гравець не чекав завантаження острова продавця), реалізовано систему боргів:
1. **Миттєва видача:** Коли гравець купує предмет на Hub-сервері (за валюту сайту, підв'язка якої вже є в RealMarket), предмет **миттєво** створюється (спавниться) або видається покупцю в інвентар.
2. **Запис боргу:** У базу даних записується "борг" продавця — кількість проданих предметів, які тепер потрібно вилучити з його ME Мережі на острові.
3. **Вилучення предметів (Запуск острова):**
   - API автоматично ініціює запуск сервера острова (якщо він був офлайн) через накопичений борг.
   - Коли острів онлайн, мод на острові отримує через WebSocket команду на погашення боргу (вилучення `X` предметів з мережі через блок `Market Link`).
   - Мод вилучає предмети та відправляє підтвердження про успішне погашення боргу назад в API.
4. **Обробка помилок (Дефіцит):** Якщо предметів у ME Мережі немає (наприклад, продавець забрав їх вручну перед зупинкою сервера):
   - Мод повинен здійснити `N` спроб вилучення.
   - Якщо після `N` спроб предмети не знайдені, мод повинен надіслати спеціальне сповіщення (Alert) Адміністратору про невдачу.
   - **Важливо:** Скасовувати транзакцію чи забирати предмети у покупця НЕ ПОТРІБНО. Ситуацію буде виправляти адміністрація вручну.

## 5. Система територій (Плотів) на Hub-сервері
Для фізичного розміщення магазинів на спавні (Hub):
1. **Генерація плотів:** Мод повинен вміти генерувати та розмічати спеціальні території (плоти) за визначеними координатами на Hub-сервері.
2. **Приват та забудова:** Власник плоту (команда/острів) отримує ексклюзивні права на будівництво та розміщення блоків магазину в межах цієї території.
3. **Телепортація:** Потрібно реалізувати систему (команди або UI меню), щоб гравці могли легко телепортуватися до конкретних магазинів на плотах.
4. **Підписка (Оренда плоту):**
   - Володіння плотом працює за моделлю щомісячної підписки.
   - Мод повинен реалізувати обробку спеціальної команди (яка буде відправлятися сервером/API) для щомісячного списання плати або перевірки статусу.
   - Якщо підписка не оплачена — плот може бути заморожений, а товари недоступні для продажу.

## 6. Технічні вимоги до коду
- **Клієнт WebSocket:** Мод повинен використовувати надійний WebSocket клієнт для підключення до API. Враховуйте необхідність автоперепідключення у разі розриву з'єднання.
- **Асинхронність:** Сканування великих ME Мереж та відправка мережевих запитів **не повинні** виконуватися в основному потоці сервера (main thread), щоб не викликати "фрізів" (lag spikes).
- **Сумісність:** Мод має бути сумісним із Java 17 та Forge (наприклад, версії 1.20.1, яка використовується в Nestworld).
